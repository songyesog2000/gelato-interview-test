# 轨迹标注工具

## 用途

配合"AI Agent 编码笔试"的人工复核环节使用：把 Claude Code CLI（或 Codex CLI）导出的原始会话
`.jsonl` 文件载入网页，按"一次实际指令对应一条记录"的粒度浏览整条轨迹，并为每条记录填写核查结论
与问题标注（编号 P01/P02…、错误类型 E01-E08/ENV/USER/OTHER、问题现象、判断理由、影响与恢复、
改进建议），最终导出为可粘贴进交付表格的 CSV。

## 项目结构（三部分）

- `server/` — 后端：Express 服务，负责登录鉴权、解析 `.jsonl`、读写标注数据、导出 CSV。
  - `lib/jsonlParser.js` 把原始行按"真实用户输入 vs. 工具返回"拆分为一条条记录。
  - `lib/annotationSchema.js` 集中定义阶段/结论/错误类型等枚举，避免前后端各写一份。
  - `lib/roster.js` 读取候选人"代码→姓名"名单（`server/config/candidates.json`）。
  - `middleware/auth.js` 基于签名 cookie 的登录校验，每次请求都会重新核对名单。
  - `storage/fileStore.js` 文件系统读写，按候选人代码隔离目录，并做了路径穿越防护。
  - `routes/api.js` REST 接口。
- `public/` — 前端：纯静态页面（无构建步骤），登录、加载会话、逐条标注、保存、导出、导入、重命名。
- `data/candidates/<候选人代码>/` — 每位候选人独立的数据目录（不入库，见 `.gitignore`）：
  - `trajectories/` 存放该候选人的原始会话文件；支持子文件夹分组，例如
    `trajectories/batch1/session.jsonl`。
  - `annotations/*.json` 存放该候选人页面保存的标注结果。
  服务器会按登录 cookie 里的代码自动路由到对应目录，候选人之间互相看不到、也访问不到对方的文件。
- `samples/` — 仓库自带的参考样本（`.jsonl` 文件会一起入库），供所有候选人练习标注流程用，页面会
  自动把它显示在侧边栏，标记为只读，不能通过页面重命名或覆盖。

## 功能

- 用面试官分配的专属代码登录：代码即凭证，无需注册。登录态存在签名、httpOnly 的 cookie 里，
  服务端每次请求都会重新对照名单校验，面试官在 `candidates.json` 里删掉一行即可让该代码立刻失效，
  不需要重启服务。
- 自动扫描该候选人自己的 `trajectories/`（含子文件夹，按文件夹名分组显示）和全体共享的
  `samples/`（固定分组"样本参考（只读）"），无需手动把文件放到某个约定路径下再刷新——放进去或
  删掉都会在下次刷新时自动反映。
- 页面内直接导入：点击"导入会话"选择本地 `.jsonl` 文件、可选填一个分组名，文件会被保存到该候选人
  自己的目录下并立刻出现在列表里；其他候选人看不到这份文件。
- 侧边栏每个会话文件旁的"✎"按钮可以重命名：会同时重命名磁盘上的 `.jsonl` 文件本身，并把已保存的
  标注数据迁移到新文件名下，不会丢失已填写的内容。样本文件是只读参考，不显示重命名按钮。
- 解析选中的会话：按"是否为真实用户输入"切分记录，其余助手回复/工具调用/工具返回归入对应记录，
  可展开查看每条事件的摘要文本。
- 为每条记录填写：阶段、本次输入（可编辑）、核查结论、若干条问题标注、异常与疑点。
- 顶部一次性填写整份会话的作答人、使用工具、模型配置、最终代码链接。
- 保存标注到本地 JSON 文件；导出为 UTF-8 BOM CSV，列顺序对应交付表字段。

## 输入 / 输出

- 输入：登录后该候选人自己的 `trajectories/`（可分子文件夹）或全体共享的 `samples/` 下的 `.jsonl`
  会话文件（一行一个 JSON 事件），既可以在服务器上用命令行直接放进对应候选人的目录，也可以在页面
  上用"导入会话"上传。
- 输出：`data/candidates/<代码>/annotations/<trajectoryId 中的 "/" 替换为 "__">.json`
  （结构化标注数据），以及导出的同名 `.annotations.csv`。

## 运行

### 首次配置候选人名单

```bash
cp server/config/candidates.example.json server/config/candidates.json
# 编辑 candidates.json，填入真实的 "代码": "姓名" 对照表
```

`candidates.json` 已加入 `.gitignore`，不会被提交；只有 `candidates.example.json` 模板入库。
服务启动时会检查这个文件是否存在、格式是否合法，缺失或代码含非法字符会直接拒绝启动并提示原因。

### 本地运行

```bash
npm install
npm start
# 打开 http://localhost:4173，用 candidates.json 里配置的某个代码登录
```

参考样本（`samples/sample-trajectory.jsonl`）无需任何操作，任何候选人登录后都会直接看到它，
分组为"样本参考（只读）"。

### 部署到公网

1. 设置环境变量 `COOKIE_SECRET` 为一个随机字符串（例如 `openssl rand -hex 32` 的输出），用来签名
   登录 cookie；不设置的话服务会用一个仅供本地开发的默认值启动，并打印警告——不要把这个默认值用
   在公网环境。
2. 反向代理（nginx/Caddy 等）负责 TLS 终止；应用已经设置了 `trust proxy`，会正确识别
   `X-Forwarded-Proto`，从而在 HTTPS 环境下给登录 cookie 加上 `Secure` 标记。
3. 登录接口 `/api/login` 按来源 IP 做了限流（10 分钟内最多 20 次），降低代码被暴力枚举的风险；
   代理层如果会改写来源 IP，请确认转发了正确的 `X-Forwarded-For`。
4. 候选人之间的数据严格按登录代码隔离在各自的 `data/candidates/<代码>/` 目录下，面试官如需查看
   某位候选人的原始会话或标注结果，直接到服务器上按代码找对应目录即可，页面本身不提供跨候选人的
   查看入口（见下方"限制"）。

## 限制

- JSONL 解析针对 Claude Code CLI 的会话事件格式（`type: user/assistant/system`，
  工具调用与返回内嵌在 `message.content` 数组里）。Codex CLI 的 `rollout-*.jsonl` 事件结构不同，
  未知/不匹配的行会被保留展示为"未分类事件"，不会丢失，但不会像 Claude Code 的记录那样按真实用户
  输入正确切分。
- 登录只有"代码即凭证"一层，没有账号名/密码或多因素校验，安全性完全依赖代码本身的随机性和
  `candidates.json` 不被泄露；面试官需要保证分发给每位候选人的代码足够随机、不易猜测。
- 没有面试官/管理员视图：不提供任何跨候选人浏览数据的页面入口，查看全部候选人的提交需要直接访问
  服务器文件系统。
- 会话态是无状态 cookie（签名后的代码本身），没有服务端 session 存储，也没有"踢下线"或多设备登录
  限制；同一个代码可以同时在多台设备上登录。
- 导入接口按单个文件接收 JSON 请求体，未针对超大文件（数十 MB 以上）做流式处理。
- 分组目前只用于展示和导入时的目标路径，重命名操作不支持跨分组移动文件（只能改同目录下的文件名）。
- 标注数据以单个 JSON 文件持久化，不适合同一候选人从多个设备并发写入同一份标注；本工具面向单次
  笔试的人工复核场景，数据量与使用方式决定了这一取舍足够。
