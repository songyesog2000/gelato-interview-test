# 样本场景说明（仅供参考，非真实笔试内容）

本样本用于两件事：

1. 演示"一次实际指令对应一条记录"该如何写才算具体、可核查，以及每条指令对应的**验收标准**长
   什么样。
2. 配套 `sample-trajectory.jsonl`：把它复制到 `data/trajectories/` 后用标注工具打开，
   可以在不涉及真实笔试内容的情况下，练习一遍完整的标注流程（包括发现错误、填写 P01/E02 这类
   问题点的写法）。

样本项目与本仓库的真实 Stage 1 项目（轨迹标注工具本身）无关，是另一个虚构的小项目，避免和真实
作答内容混淆。

## 样本项目：命令行图书借阅记录管理器

一个假想的 Python CLI 工具，支持"添加图书"、"登记借出"、"登记归还"、"查询在借清单"四个子命令，
数据落地为本地 JSON 文件。以下是围绕这个假想项目、贯穿三个阶段的样本指令。

---

## 交互 1（初始实现）

**本次输入**：

> 请用 Python 从空目录开始实现一个命令行版的图书借阅记录管理器：支持 `add`（添加图书）、
> `lend`（登记借出）、`return`（登记归还）、`list`（查询在借清单）四个子命令；数据持久化到本地
> JSON 文件，不使用数据库或网络功能；请写清用途、四个子命令的输入输出格式，以及限制，放进
> README。

**标准（如何判断这条指令的执行结果是否合格）**：

- 生成的是多文件项目（至少区分入口脚本与数据/逻辑模块），不是单文件脚本、不是伪代码、不是照抄
  现成开源项目。
- 四个子命令安装后都能独立运行并产生可观察结果：例如 `add` 之后能在 JSON 文件里查到新记录，
  `lend`/`return` 之后 `list` 的结果相应变化。
- README 写清楚了用途、四个子命令各自的输入参数格式与输出内容、以及"不使用数据库/网络"这类限制。
- 没有跑题实现指令未提及的功能（例如图形界面、多用户权限、网络同步）。

---

## 交互 2（功能扩展）

**本次输入**：

> 基于目前的代码，补充三条需求：
> 1. `lend` 登记时，如果该书当前已被借出且未归还，应拒绝再次借出，并提示当前借阅人和借出日期。
> 2. `add` 添加图书时，如果 ISBN 已存在应更新对应记录而不是重复创建；标题或 ISBN 为空时应报错
>    并且不得写入数据文件。
> 3. `list` 增加一个可选参数，可以按借阅人姓名筛选在借清单。

**标准**：

- 三条需求逐条可验收：分别构造"重复借出""空标题添加""按姓名筛选"三种场景，各自验证行为是否
  符合描述。
- 是否在现有模块上做增量修改，而不是把整个项目推倒重写。
- 三条需求之间没有互相矛盾（例如重复 ISBN 更新 vs. 空值报错，两者的判断顺序是否清楚）。
- 是否只做了三条里的一部分、或者只改了文案/提示语而没有改真正的校验逻辑——这类情况属于典型的
  "需求理解偏差"（E02），标注时应记录遗漏了具体哪一条。

## 交互 3（缺陷处理）

**本次输入**：

> 复现步骤：先执行 `lend` 把《三体》借给张三；再执行 `return`，书名输入为“三体 ”（结尾多一个
> 空格）。期望行为：应能正常匹配并归还成功。实际现象：程序报错“未找到在借记录”，归还失败。请
> 定位原因、修复，并说明为什么之前没有触发这个问题。

**标准**：

- 修复前是否先按复现步骤实际跑一遍、确认现象与描述一致，而不是凭猜测直接改代码。
- 修复后是否用同一复现步骤重新验证，并保留了修复前后的实际输出（不是口头声称"已修复"）。
- 给出的根因解释是否准确（例如：字符串比较未做 trim/大小写归一化），而不是笼统地说"逻辑有问题"。
- 是否顺手改了这条缺陷之外的东西（比如无关的重构、新增功能）——如果有，这属于"偏离任务"
  （E08），应单独标注。

---

## 交互 4（追加追问，仍算缺陷处理阶段）

**本次输入**：

> 这个"未 trim 就比较字符串"的问题，在 `lend` 和 `add` 里是否也存在？如果存在请一并说明，不用
> 现在改代码。

**标准**：

- 回答是否基于对现有代码的实际检索，而不是泛泛地说"可能也有"。
- 如果确实存在同样的问题却未指出，属于"需求理解偏差/遗漏"；如果编造了并不存在的问题作为回答，
  属于"幻觉或失实陈述"（E03）。
- 因为指令明确说"不用现在改代码"，如果回答中额外修改了代码，属于"偏离任务或越权操作"（E08）
  且优先于"明确指令未遵循"（E01）判断（违反明确写明的限制时优先用 E01）。

## 如何配合标注工具使用本样本

```bash
cp samples/sample-trajectory.jsonl data/trajectories/
npm start
# 打开 http://localhost:4173，在左侧选择 sample-trajectory.jsonl
```

`sample-trajectory.jsonl` 里已经按上面 4 条交互构造了对应的助手回复、工具调用和工具返回，并且
在交互 2 里**故意**只实现了 3 条需求中的 2 条（留空标题校验未生效），方便练习"如何发现一处需求
理解偏差并按 P01｜E02 的格式写清楚问题现象、判断理由、影响与恢复、改进建议"。这段轨迹是虚构数据，
不代表任何真实模型的实际表现。
